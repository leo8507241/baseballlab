## 步驟

### 1. 逐頁檢查線上版

打開 Space 網址，四個頁面都點一遍，每個互動元件都操作一次：

- 首頁：卡片、戰績表
- 數據學院：14 個數據都點過，改計算機的數字
- 觀察室：六隊都切換，點散佈圖的點
- 預測頁：換場次、換先發、拿掉一位打者

有紅色錯誤框的地方，記下頁面和操作。

### 2. 常見問題與解法

| 狀況 | 原因 | 解法 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'plotly'` | `requirements.txt` 少寫套件 | 補上後重新上傳 |
| `FileNotFoundError: data/clean/...` | 檔案沒上傳，或 `.gitignore`／`ignore_patterns` 排除了 | 檢查 Space 的「Files」分頁有沒有這個檔案 |
| 本機正常、線上找不到檔案 | Linux 大小寫有差，`Teams.csv` 和 `teams.csv` 是不同檔案 | 統一用小寫檔名 |
| 線上跟本機畫面不一樣 | Streamlit 版本不同 | `README.md` 的 `sdk_version` 要跟 `requirements.txt` 一樣 |
| 很久沒人用，打開要等 | 免費 Space 閒置會休眠 | 正常現象，等 1 分鐘會醒來 |

看錯誤細節：Space 頁面右上角「⋮」→「Logs」，最下面通常就是錯誤原因。

### 3. 確認網站不會在開頁時爬資料

網站只應該讀 `data/clean/` 裡存好的檔案。如果頁面裡有爬資料的程式碼，每位訪客打開網頁都會去打野球革命的 API，對方網站沒回應時整頁就會壞掉。檢查四個頁面：

> **Jupyter**：可以在格子裡執行，每一行指令前面加 `!`。

```bash
grep -n "get_json\|cached_json\|fetch\." pages/*.py
```

`grep` 會搜尋檔案裡的文字。**應該沒有任何結果**；有的話，把那段改成先在 `scripts/update_data.py` 抓好存檔，頁面再讀檔案。

> 台灣大賽的實際結果要到最後一天揭曉時才抓，而且也是先存成檔案，再讓網站讀。

### 4. 測試「網路斷線」的情況

把電腦的 Wi-Fi 關掉，在本機啟動網站：

> **一定要在終端機執行**：網站會一直執行，用 `!` 跑會讓 notebook 卡住。在 JupyterLab 用 **File → New → Terminal** 開一個終端機執行。

```bash
streamlit run app.py
```

四個頁面都應該正常顯示，因為資料全部來自 `data/clean/`。測完記得打開 Wi-Fi。

### 5. 重新部署

> **Jupyter**：可以在格子裡執行，每一行指令前面加 `!`（例如 `!python scripts/update_data.py`）。

```bash
python scripts/update_data.py
python scripts/deploy.py
```
