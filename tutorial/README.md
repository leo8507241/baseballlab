# 好球帶研究室：從零做出中職進階數據網站

這是一份 34 天的教學，每天約 2 小時，從 2026/10/11 做到 11/15。完成後會有一個部署上線的 Streamlit 網站，以及一份模型穩定性實驗報告。網站包含四個頁面：

| 頁面 | 內容 |
| --- | --- |
| 首頁 | 主視覺、球季數據亮點、加上畢氏勝率的全年戰績、中職官網的上下半季戰績 |
| 數據學院 | 14 個進階數據的白話解釋、中職分布、互動計算機 |
| 球季觀察室 | 球隊雷達圖、話題球員標籤、ERA vs FIP 散佈圖、球員卡 |
| 台灣大賽預測 | 奪冠機率（附 95% 區間）、自選先發與打線的單場分析、弱點與策略、賽後對照 |

這份教學依照[專案企劃書](https://claude.ai/code/artifact/2b67c4db-f2c6-46fd-bf31-5f2800437571)的內容與時程安排。

## 怎麼使用這份教學

- 一天一個檔案，照日期打開，從「今天的目標」讀到「完成檢查」。
- **第一次出現的觀念**會附完整程式碼和逐段解釋，照著打（建議自己打，不要複製貼上，會記得比較牢）。
- **重複類型的工作**會標「練習」，先自己寫，卡住再打開「參考解答」。
- 每天結束都要做 `git commit`，就算當天沒做完也 commit，隔天才知道停在哪裡。
- 緩衝日只有 10/25 和 11/15 兩天，落後的話優先用這兩天補。
- 教學裡的程式碼都已經實際跑過；如果你跑出不一樣的結果，先看當天的「常見錯誤」。

## 用 Jupyter 做的方式

教學可以全部在 JupyterLab 完成（Day 1 第 7 步會設定好）。每段程式碼前面都有標註：

| 標註 | 怎麼做 |
| --- | --- |
| `%%writefile 檔名` | 新的一格，第一行寫 `%%writefile 檔名`，下面貼程式碼，執行後存成檔案（會覆蓋） |
| `%%writefile -a 檔名` | 同上，但是**加到檔案最後面**；第二行留空，跟前面的程式隔開 |
| 打開檔案修改 | 程式碼要插進檔案中間時，在 JupyterLab 左側雙擊打開 `.py` 檔直接改，`Cmd + S` 存檔 |
| 直接貼在格子執行 | 探索、測試用的程式碼，不用存成檔案 |
| 前面加 `!` | 終端機指令也能在格子裡跑，例如 `!python scripts/update_data.py`、`!git add .` |
| **一定要在終端機執行** | 在 JupyterLab 用 **File → New → Terminal** 開終端機執行 |

**一定要在終端機執行的事情**只有這幾種：

| 指令 | 原因 |
| --- | --- |
| `python3 -m venv`、`source .venv/bin/activate` | 建立、啟用虛擬環境 |
| `jupyter lab` | 要從啟用 `.venv` 的終端機啟動，`!pip`、`!python` 才會用專案的環境 |
| `streamlit run app.py` | 網站會一直執行，用 `!` 跑會讓 notebook 卡住 |
| `git push`（第一次） | 可能要輸入帳號和 token，`!` 沒辦法輸入 |
| `hf auth login` | 要貼上 token |

**每天的開始方式**：

```bash
cd ~/Desktop/線上課程教材/pythan基礎觀念/爬蟲/好球帶研究室
source .venv/bin/activate
jupyter lab
```

在 `notebooks/` 新增當天的筆記本（例如 `D03.ipynb`），Kernel 選「好球帶研究室 (.venv)」，第一格放每日開場程式碼：

```python
%cd ~/Desktop/線上課程教材/pythan基礎觀念/爬蟲/好球帶研究室
%load_ext autoreload
%autoreload 2
```

`%autoreload 2` 讓你改了 `src/` 的 `.py` 檔之後，不用重啟 kernel 就能用新版本。在終端機跑 `streamlit run app.py` 的同時，可以繼續在筆記本裡測試函式。

## 為什麼是這個順序

1. **先資料、後網頁**（Day 1–13）：網頁只是把算好的數字畫出來。資料和模型先做對，網頁才不會一直改。
2. **兩個資料來源同步**（Day 2–5）：中職官網提供官方的上下半季戰績，野球革命提供球員和逐打席資料，兩者交叉比對；官網抓不到時自動改用野球革命（Plan B）。
3. **台灣大賽打完再做賽後對照**（Day 18）：台灣大賽 10/17–10/25 進行，資料層在比賽期間完成，比賽打完剛好可以對照預測和真實結果。
4. **11/8 前部署上線**（Day 26–28）：第一次上線幾乎一定會遇到問題，所以留了三天。
5. **最後一週做上線後實驗**（Day 29–33）：測試模型的穩定性，把不穩定的地方在網站上誠實標示，並寫成實驗報告。
