## 今天的目標

- 用開發者工具找出官網戰績頁背後的 `seasonaction`，學會送 **POST** 請求
- 一個網址、換 `SeasonCode` 就抓到**上下半季戰績**，用 BeautifulSoup 解析

## 為什麼要做這一步

企劃書的資料來源是「中職官網和野球革命同步進行」。兩個來源各有用處：

| 來源 | 拿得到什麼 | 特點 |
| --- | --- | --- |
| 中職官網 | 上下半季戰績 | 官方數字；不同網路環境不一定打得開 |
| 野球革命 | 全年戰績、球員成績、逐打席紀錄 | 有 API，資料最完整 |

半季戰績很重要：中職是上下半季各出一個冠軍，季後賽的資格就是這樣決定的。用兩個來源互相驗證，也是資料工程很重要的習慣：**一個數字如果兩個來源都對得上，才比較可信**。

今天也會學第二種爬蟲方法：Day 2–4 是用 GET 抓 API 回傳的 JSON，今天是用 POST 送查詢、再解析回傳的 HTML。

## 步驟

### 1. 先用瀏覽器觀察官網的戰績頁

1. 打開 [中職官網的球隊戰績頁](https://www.cpbl.com.tw/standings/season)，上面有一個下拉選單可以選「全年度」「上半季」「下半季」。
2. 按 `F12`（Mac 是 `Cmd + Option + I`）打開開發者工具，切到 **Network** 分頁。
3. 把下拉選單換成「上半季」，Network 會多出一筆 `seasonaction`。點它看：
   - **Headers**：Request Method 是 `POST`（不是 Day 2–4 用的 `GET`）。
   - **Payload**：送出去的資料裡有 `SeasonCode: 1`，換成下半季就變 `2`，全年是 `0`。還有一個很長的 `__RequestVerificationToken`。
   - **Response**：回來的是一段 HTML，裡面就是戰績表格。

所以只要對 `seasonaction` 送一次 POST，換 `SeasonCode` 就能拿到上半季或下半季，**一個網址就搞定**。

那個 `__RequestVerificationToken` 是官網的防偽驗證碼：要先打開戰績頁（`/standings/season`），頁面裡藏著一組驗證碼，送 POST 的時候帶回去，官網才會回答。而且要用同一個 `requests.Session()`，因為驗證碼跟 cookie 是一對的。

> 官網在不同網路環境下不一定打得開（之前在海外網路會被導回首頁）。所以下面還是要準備 Plan B。

### 3. 新增 `src/cpbl.py`，一步抓下上下半季戰績

> **Jupyter**：新的一格，第一行寫 `%%writefile src/cpbl.py`，下面貼這段，執行後就會存成檔案（會覆蓋同名檔案）。

```python
"""中職官網（cpbl.com.tw）：抓上、下半季戰績，並跟野球革命交叉比對。

官網抓不到時，改用野球革命的比賽結果自己算（Plan B）。
"""
import pandas as pd
import requests
from bs4 import BeautifulSoup

from src.fetch import HEADERS, RAW_DIR, fetch_games

CPBL = "https://www.cpbl.com.tw"
HALF_CODES = {"上半季": "1", "下半季": "2"}   # 官網的 SeasonCode：0 全年、1 上半季、2 下半季
HALF_GAMES = 180                              # Plan B 用：全年 360 場，第 1–180 場是上半季

def fetch_cpbl_standings(season_code, refresh=False):
    """抓中職官網的戰績表 HTML：先開戰績頁拿驗證碼，再 POST 到 seasonaction。"""
    cache = RAW_DIR / f"cpbl_standings_{season_code}.html"
    if cache.exists() and not refresh:
        return cache.read_text(encoding="utf-8")
    session = requests.Session()
    session.headers.update(HEADERS)
    page = session.get(f"{CPBL}/standings/season", timeout=20)
    page.raise_for_status()
    token = BeautifulSoup(page.text, "html.parser").find("input", {"name": "__RequestVerificationToken"})["value"]
    res = session.post(f"{CPBL}/standings/seasonaction",
                       data={"__RequestVerificationToken": token, "Kindcode": "A", "SeasonCode": season_code},
                       headers={"X-Requested-With": "XMLHttpRequest", "Referer": f"{CPBL}/standings/season"},
                       timeout=20)
    res.raise_for_status()
    cache.parent.mkdir(parents=True, exist_ok=True)
    cache.write_text(res.text, encoding="utf-8")
    return res.text

def parse_standings(html, half):
    """拿回傳 HTML 的第一張表（戰績表），拆出球隊和勝、敗、和。"""
    table = BeautifulSoup(html, "html.parser").find("table")
    rows = []
    for tr in table.find_all("tr")[1:]:
        cells = [td.get_text(" ", strip=True) for td in tr.find_all("td")]
        if len(cells) < 3:
            continue
        team = cells[0].split()[-1]                  # 第一格是「1 味全龍」，取最後一段
        w, t, l = (int(x) for x in cells[2].split("-"))
        rows.append({"half": half, "team": team, "W": w, "L": l, "T": t})
    return pd.DataFrame(rows)

def cpbl_half_standings(refresh=False):
    """上半季、下半季各抓一次，接成一張表。"""
    frames = [parse_standings(fetch_cpbl_standings(code, refresh), half)
              for half, code in HALF_CODES.items()]
    return pd.concat(frames, ignore_index=True)
```

逐段說明：

- `requests.Session()`：一個會記住 cookie 的連線。先用它 `get` 戰績頁、再用它 `post`，官網才認得是同一個人。
- `find("input", {"name": "__RequestVerificationToken"})["value"]`：在戰績頁裡找到藏起來的驗證碼。
- `session.post(..., data={...})`：POST 要送的資料放在 `data`，就是你在 Payload 看到的那幾個欄位。`Kindcode: "A"` 是一軍例行賽。
- 快取跟 Day 3 的 `cached_json` 一樣，只是存的是 HTML 文字，檔名用 `SeasonCode` 區分。
- `parse_standings`：回傳的 HTML 有好幾張表，第一張是戰績表。每一列的第一格是「排名 隊名」，第三格是戰績。
- **注意順序**：官網寫的是「**勝-和-敗**」（例如 `39-0-21`），所以拆的時候是 `w, t, l`，不是 `w, l, t`。這種小地方最容易出錯，交叉比對就是用來抓這種錯的。
- `HEADERS`、`RAW_DIR`、`fetch_games` 直接從 `fetch.py` 拿來用，不重複寫。

### 4. 練習：Plan B，用野球革命自己算

如果官網抓不到，就用 Day 4 的 `fetch_games()` 自己算。寫 `half_standings_from_rebas()`，回傳跟上面一樣格式的表格（`half`、`team`、`W`、`L`、`T`）。

提示：

- 一季 360 場，**第 1–180 場是上半季**（用 `seq` 欄位判斷）。
- 主隊贏是 `winner_side == "HOME"`，客隊贏是 `"AWAY"`，和局是 `"TIE"`。

> 為什麼不用日期切（例如 7/3 之前算上半季）？因為延賽的比賽會在之後補賽。用日期切的話，統一和兄弟會有 1 場被算到錯的半季，跟官網對不上。用場次編號才對得上。

<details>
<summary>參考解答</summary>

> **Jupyter**：新的一格，第一行寫 `%%writefile -a src/cpbl.py`（`-a` 是加到檔案最後面，不會覆蓋），第二行留空，再貼這段。

```python
def half_standings_from_rebas():
    """Plan B：用野球革命的比賽結果，依「第幾場」切成上下半季自己算。"""
    games = fetch_games()
    games["half"] = games["seq"].astype(int).map(lambda s: "上半季" if s <= HALF_GAMES else "下半季")
    rows = []
    for half, g in games.groupby("half"):
        for team in pd.unique(g[["away", "home"]].values.ravel()):
            m = g[(g["away"] == team) | (g["home"] == team)]
            win = (((m["home"] == team) & (m["winner_side"] == "HOME"))
                   | ((m["away"] == team) & (m["winner_side"] == "AWAY"))).sum()
            tie = (m["winner_side"] == "TIE").sum()
            rows.append({"half": half, "team": team, "W": int(win), "L": int(len(m) - win - tie), "T": int(tie)})
    return pd.DataFrame(rows)
```

- `games[["away", "home"]].values.ravel()`：把客隊、主隊兩欄攤平成一串，再 `pd.unique` 取出所有球隊。
- 每一隊找出自己參與的比賽，數主場贏和客場贏的場數。

### 5. 先試官網，失敗才用 Plan B

> **Jupyter**：新的一格，第一行寫 `%%writefile -a src/cpbl.py`（`-a` 是加到檔案最後面，不會覆蓋），第二行留空，再貼這段。

```python
def half_standings(refresh=False):
    """先試中職官網，失敗才用野球革命。回傳（表格, 來源）。"""
    try:
        df = cpbl_half_standings(refresh)
        if len(df) == 12:
            return df, "中職官網"
        print(f"官網戰績表只解析到 {len(df)} 列，改用野球革命")
    except (requests.RequestException, TypeError) as e:
        print(f"中職官網抓不到（{e}），改用野球革命")
    return half_standings_from_rebas(), "野球革命（備案）"
```

這就是「官網優先、野球革命備案」：`try` 裡面先抓官網，連線失敗、被導回首頁找不到驗證碼（`TypeError`），或解析出來的列數不對，都改用 Plan B。回傳時順便告訴你資料來自哪裡，網站上可以標示來源。

### 6. 交叉比對

> **Jupyter**：新的一格，第一行寫 `%%writefile -a src/cpbl.py`（`-a` 是加到檔案最後面，不會覆蓋），第二行留空，再貼這段。

```python
def cross_check(half, season):
    """上半季 + 下半季 應該等於野球革命的全年戰績；回傳對不上的球隊。"""
    total = half.groupby("team")[["W", "L", "T"]].sum()
    full = season.set_index("team")[["W", "L", "T"]]
    diff = (total - full).abs().sum(axis=1)
    return diff[diff > 0]
```

`half.groupby("team")[["W", "L", "T"]].sum()` 把上下半季加起來，再減掉野球革命的全年戰績。全部是 0 就代表兩個來源一致。

## 常見錯誤

| 狀況 | 原因與解法 |
| --- | --- |
| 解析出 0 列 | 官網改版了。用開發者工具重新看表格結構，調整篩選條件 |
| `TypeError: 'NoneType' object is not subscriptable` | 戰績頁裡找不到驗證碼，通常是被導回首頁了（網路環境的關係）。`half_standings()` 會自動改用 Plan B |
| 勝敗剛好相反、交叉比對全部對不上 | 官網是「勝-和-敗」，拆成 `w, t, l` |
| 直接用 `requests.post` 得到 400 或 500 | 少了驗證碼，或 GET 和 POST 沒用同一個 `Session` |
| `ModuleNotFoundError: bs4` | 套件名稱是 `beautifulsoup4`，`pip install beautifulsoup4` |
| 用日期切的 Plan B 對不上 | 延賽補賽的關係，改用 `seq`（場次編號）切 |
